# dev/ —— 开发时手工跑的东西

这里放的**不是产品代码，也不是自动化测试**。是开发和排障时人手动去跑的辅助程序。

为什么单开一个目录、而不是叫 `tools/`：这个产品里「工具」已经有确定含义了——MCP、skill
这些模型能调的东西，代码里到处这么叫。顶层再来个 `tools/`，第一眼会以为是那个。

## 跟 `tests/` 的区别

| | 谁跑 | 什么时候 | 跑挂了意味着 |
|---|---|---|---|
| `tests/` | 机器 | 每次提交、CI | **代码坏了，必须修** |
| `dev/probe/` | 人 | 换环境时验一次 | 这台机器不支持某个特性（是个结论，不是故障） |
| `dev/mock/` | 人 | 联调期间起着不关 | 服务没起起来，重跑即可 |

`tests/` 挂了要拦住提交；这里的挂了不拦任何东西。所以它们不能混在一起——CI 分不清
什么该拦、什么不该拦。

## `mock/` —— 顶替连不上的外部服务

### `mock_mythos_server.py`

技能市场有两个数据源，其中 mythos（IPmasterMythos）是内网服务，本机大概率连不通。
这个假服务顶替它的两个接口，永远返回固定数据。

```bash
python dev/mock/mock_mythos_server.py            # 默认 127.0.0.1:9099
MOCK_MYTHOS_PORT=9099 python dev/mock/mock_mythos_server.py
```

然后让后端指向它（配置里默认是真实地址，须用环境变量盖掉）：

```bash
export NLC_SKILL_MYTHOS_BASE_URL=http://127.0.0.1:9099
```

**期望看到**：技能中心里 mythos 那一路能列出目录、能下载安装。列不出来先看后端日志里
这个地址对不对。

两个刻意的设计，改它的时候别破坏：

- **零依赖**（纯标准库，任意 python 可跑）。开发辅助工具要是自己先得装一堆依赖，
  就成了障碍。
- **老实分页**。真实 mythos 是服务端分页的，客户端会一页页翻到翻完；假服务若每次
  都返回全量，那个翻页循环**永远停不下来**——而这个 bug 只在接真服务时才暴露。

## `probe/` —— 验证这台机器支不支持某个特性

两个脚本都是**一次性诊断**，不是回归测试。它们回答的是「这个 Windows 环境能不能这么干」，
结论已经落进 `src/netlivecowork/low_integrity/` 的实现里了。留着是为了**换一台机器
（新客户环境、新 Windows 版本、装了新安全软件的机器）时能复验**。

设计背景见 `docs/全自动模式安全设计.md` §5.6。

### `win_restricted_token_spike.py`

问：普通进程能不能用自派生的受限令牌启动子进程。

```bash
python dev/probe/win_restricted_token_spike.py
```

**期望看到**：受限令牌这条路走不通（这正是当初排除它、改用低完整性级别的原因）。
如果哪天在某台机器上它**通了**，那是个值得记录的新情况，但不改变现有实现。

### `win_low_launcher_stream_spike.py`

问：低完整性子进程能不能实时流式输出，以及写入边界是否真的生效。

```bash
python dev/probe/win_low_launcher_stream_spike.py
```

**期望看到**四件事同时成立：

- 子进程每秒一行，父进程收到的时间戳 `[0.5, 1.5, 2.5]` **依次到达**（= 真流式，不是
  攒够了一起吐）
- 写工作区内 → 成功
- 写工作区外 → 被拒绝
- pid 和退出码都取得到

任何一条不成立，说明这台机器上低完整性边界不能按现有方式工作——**这时候要停下来查，
不要绕过去**，那道边界是全自动模式的安全前提。
