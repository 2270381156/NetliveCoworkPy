# 脚本触发场景识别

用于第五步：判断哪些逻辑需要写成脚本。

## 必须写脚本的场景

满足以下任一条件，主动告知用户「这部分我来写成脚本」，并立即写好：

1. 「批量处理多个文件」——循环读取、处理、输出
2. 「从某种格式解析数据」——日志、配置文件、报表解析
3. 「生成固定格式的文档或报告」——模板填充、文档生成
4. 「核对两份数据」「找出差异」——数据比对
5. 「统计数量/汇总/计算」——数值计算、统计分析
6. 「读写 CSV/JSON/Excel/YAML」——结构化数据读写
7. 「重复执行直到满足条件」——需要精确控制的循环逻辑
8. **确定性分支路由**——流程里有多个「如果是A类型就走X，如果是B类型就走Y」的硬分支。这类逻辑写进提示词 LLM 会执行不稳定，写成脚本才能保证每次结果一致

**判断要不要写脚本的核心问题：这件事的结果必须精确且每次一样吗？**
- 是 → 写脚本
- 否（允许 LLM 灵活发挥）→ 写进 references 作为原则指导

## 脚本写作规范

- 语言：Python（最通用）
- 文件命名：动词+对象，如 `parse_log.py`、`generate_report.py`
- 开头必须有注释说明：
  ```python
  # 功能：[这个脚本做什么]
  # 用法：python scripts/xxx.py <参数1> <参数2>
  # 输出：[输出到哪里，什么格式]
  ```
- 所有注释用中文
- 在 SKILL.md 的对应步骤里写调用方式

## 多个脚本时

创建 `scripts/README.md`，列出所有脚本的功能和调用方式。
