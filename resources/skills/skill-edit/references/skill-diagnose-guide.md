# Skill 问题诊断指南

用于改进流程第二步：定位问题出在哪一层。

## 诊断流程

拿到用户描述的问题和 skill 文件后，依次检查以下层次，找到根源。

---

## 第一层：触发层（description 字段）

**问题现象：**
- Skill 在不该触发时触发了（误触发）
- 用户明确说了触发词但 skill 没有启动（漏触发）

**检查方式：** 读 SKILL.md 的 `description` 字段，看触发描述是否太宽或太窄。

**修改方向：**
- 触发太宽 → 补充更具体的限定条件，或加上「不触发」的反例
- 触发太窄 → 补充用户实际用的表达方式（尤其是口语化说法）

---

## 第二层：流程层（SKILL.md 步骤）

**问题现象：**
- Claude 跳过了某个步骤
- Claude 做了步骤但顺序不对
- Claude 没有向用户要必要的信息就直接输出了
- 某个步骤的描述太模糊，Claude 每次做法不一样

**检查方式：** 逐步对照 SKILL.md，看哪一步的描述和实际出问题的行为对应。

**常见原因和修改方向：**

| 现象 | 原因 | 修改方式 |
|-----|-----|---------|
| Claude 跳步 | 步骤描述没有说「必须」或前置条件不明确 | 加上「在X完成之前不要进行Y」 |
| 做法每次不一样 | 步骤描述太抽象，没有说清楚做到什么程度 | 把抽象动词改成具体动作 |
| 没要信息就输出 | 缺少「如果信息不完整，先问用户」的步骤 | 在流程前加一个信息收集步骤 |
| 输出格式乱 | SKILL.md 里描述了格式但不够清晰 | 把格式移到 templates/，步骤里写「按 templates/xxx.md 格式输出」 |

---

## 第三层：知识层（references/ 文件）

**问题现象：**
- Claude 做了步骤，但判断结果不对
- Claude 遗漏了某类情况
- Claude 的判断标准和用户期望的不一致

**检查方式：** 找到 SKILL.md 里引用了 references 的步骤，读对应的 references 文件，看知识是否准确完整。

**常见原因和修改方向：**

| 现象 | 原因 | 修改方式 |
|-----|-----|---------|
| 遗漏了某类情况 | references 没有覆盖这种场景 | 补充对应的规则或例子 |
| 判断标准和期望不一致 | 标准描述太模糊，或用了歧义词 | 改成更具体的表述，加例子说明 |
| 大量分支导致执行不稳定 | 分支逻辑不应该放在提示词里 | 把分支逻辑改写成脚本 |

---

## 第四层：脚本层（scripts/ 文件）

**问题现象：**
- 脚本报错或输出格式不对
- Claude 没有调用脚本，直接用自己的逻辑处理了
- 脚本处理结果 Claude 没有正确使用

**检查方式：** 看 SKILL.md 里是否明确写了「运行 scripts/xxx.py」，脚本本身逻辑是否正确。

**常见原因和修改方向：**

| 现象 | 原因 | 修改方式 |
|-----|-----|---------|
| Claude 没调用脚本 | SKILL.md 步骤里没写清楚「运行脚本」指令 | 在对应步骤加上明确的调用指令 |
| 脚本输出 Claude 没用对 | 没有说明脚本输出的格式和后续步骤的关系 | 在步骤里说明「脚本输出的结果用于…」 |

---

## 特殊情况：问题是「偶尔出现」

偶尔出错但不是每次 → 通常是提示词里有模糊的判断逻辑，LLM 在边界情况下行为不稳定。

处理方式：
1. 找到那个模糊的判断点
2. 如果是确定性逻辑 → 改成脚本
3. 如果是主观判断 → 在 references 里补充更多具体例子，帮助 LLM 校准

偶尔出错的 case 一定要加进 `evals/`，防止「修好了又退化」。
