# 什么是Skill（大白话版）

Skill就是给Claude的工作手册。你把某件事的做法写清楚，放在一个文件夹里，Claude以后碰到这类任务就按手册来——不需要你每次重新解释。

## 标准文件夹结构

```
你的skill名称/
├── SKILL.md          ← 核心文件：只写步骤，Claude照着走
├── references/       ← 专业知识、判断标准、行业规则（Claude读的文档）
├── templates/        ← 输出格式、报告模板、标准文档结构
├── scripts/          ← 需要精确计算或批量处理的逻辑（Claude来写）
├── assets/           ← 脚本要用到的数据文件（表格、词典、图标等）
├── examples/         ← 你希望结果长什么样的例子（给Claude参考）
└── evals/            ← 验收测试用例（检验skill改动后有没有出错）
```

## 每个部分放什么

**SKILL.md**：只放步骤。「先做什么、然后做什么、遇到X就做Y、最后输出Z」。不放知识，不放标准，不放模板。

**references/**：所有的「凭什么这样判断」。行业规则、评分标准、合规要求、专业术语。Claude读懂后灵活运用。步骤里写「参考 references/xxx.md」。注意：references 里放的是**原则和知识**，不是 if/else 决策树——大量分支逻辑会变成提示词喂给 LLM，而 LLM 执行确定性分支不可靠，应该写成脚本。

**templates/**：固定的输出格式。报告结构、表格格式、标准措辞。步骤里写「按 templates/xxx.md 格式输出」。

**scripts/**：需要精确、重复执行的逻辑。批量处理文件、数据计算、格式转换。Claude来写，用户只需要知道怎么运行。

**assets/**：脚本要「读入」的数据文件——端口号对照表、错误码词典、城市列表、图标文件等。**和 references/ 的区别**：references 是 Claude 理解的文档，assets 是脚本程序读取的数据，Claude 不需要「理解」它，只需要让脚本去用它。

**examples/**：你觉得结果应该长这样的例子。给 Claude 在执行时参考，知道「好的输出」是什么风格。好的案例、反面案例都可以放。

**evals/**：验收测试用例。每个用例写：给什么输入、期望什么输出、怎么判断对不对。**和 examples/ 的区别**：examples 是「参考样本」（告诉Claude怎么做），evals 是「考卷」（检验skill有没有做对）。改动skill之后跑一遍evals，确认没有退化。

## 最重要的一句话

**SKILL.md 里只放步骤，所有「知识」都放到 references/ 里。**

判断一句话该不该放进 SKILL.md 的方法：这句话是「做什么」还是「为什么这样做/按什么标准」？是「做什么」才放进去，是「标准/知识」就移到 references/。
