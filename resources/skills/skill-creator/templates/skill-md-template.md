## 写法检查清单

写完 SKILL.md 后，逐条检查：

### 结构检查
- [ ] 元数据只有 `name` 和 `description` 两个字段，写在文件开头的 `---` 之间
- [ ] 每个步骤以动词开头（祈使句）
- [ ] 每个步骤不超过 5 行，细节放 references/
- [ ] 「启动前需要准备的信息」只在确实需要用户提供信息时才保留

### 内容分类检查
- [ ] 没有大段的专业知识解释（应在 references/）
- [ ] 没有数值标准或评分规则（应在 references/）
- [ ] 没有具体的输出格式模板（应在 templates/）
- [ ] 没有计算逻辑或确定性分支路由（应写成 scripts/）
- [ ] 脚本要读取的数据文件放在了 assets/（不是 references/）

### 引用完整性检查
- [ ] 引用了 references/ 的步骤写了「参考 references/xxx.md」
- [ ] 引用了 templates/ 的步骤写了「按 templates/xxx.md 格式输出」
- [ ] 引用了脚本的步骤写了「运行 scripts/xxx.py <参数>」
- [ ] 「参考资料」节列出了所有被引用的文件，且每个文件都有用途说明
- [ ] 每个被引用的文件确实存在且内容正确

### 质量检查
- [ ] 每个检查项具体、可验证（不是「确保质量」这种空话）
- [ ] 示例展示了完整的输入和输出
- [ ] 边界明确列出了不做什么和何时暂停
- [ ] 绝对不可违反的规则真正抓住了最关键的约束

### 可测试性检查（如有 evals/）
- [ ] 如果 skill 逻辑复杂或有多个分支，考虑是否需要在 evals/ 里写验收用例
- [ ] evals/ 覆盖了典型场景、曾出错场景、边界情况
